## Multiplayer (added 2026-11-07)
Plan agreed with Eric: (1) remote-plane layer, (2) time-trial ghosts + leaderboard, (3) live races over the artifact `room`. All three are in the code.

**Platform limits found (they decide the design):**
- **Sharing (as of 2026-11-07): private, friends invited by email** (Eric set it private on purpose so invited friends get room/admin access; link sharing stays off). Earlier it was publicly shared, and the platform refuses to add `db` to a public artifact, so the shared leaderboard is still dormant (the code is built and tested, `DB` stays null). Now that it's private it can be turned on: declare `db: {rules:[{path:"tt",read:"view",write:"owner"},{path:"tt/{self}",write:"interact"}]}` plus `user {scopes:[profile]}`. Even then, on a personal plan only the owner and **Editors invited by email** (while not link-shared) can write; outside Viewers only read.
- `room`: people arriving by **public link can't connect**; signed-in people invited by email can, even as Viewers. **Presence** is open to every admitted viewer (≤4 KiB, coalesced ~30/s; emits + presence share ~40/s). **Event topics** are admin-only (Editor and up) unless opened to Contributors (never Viewers).
- **Real-world test (Eric, two Chrome tabs, same account):** both tabs connected, but `onPeers`/presence listed only the tab itself, in the lobby and in a named room alike, while `emit`/`on` messages *did* cross between the tabs. So live state now travels as an `st` event message (owner/Editors can send), with presence kept as a fallback. Consequence for friends: an outside friend needs **"Can edit"** access, which only gives admin while the artifact is **not** also link-shared. Whether presence works between two *different* accounts (which would let plain Viewers play) is still untested.
- Friends need a (free) Claude account with the exact invited email; create the account first, then invite (re-invite if the invite went out before the account existed).

**Remote-plane layer** (`makeRemoteMesh`, `disposeRemote`, `fadeRemote`): plane mesh driven by samples, not physics. Ghost meshes are translucent (opacity ≤.45, no shadows, fade further when within ~17 m of the player); live players use normal opaque planes.

**Time Trial mode** (`titleMode 'tt'`, `ttActive`): `racers=[player]`, other planes hidden, grid centre, no pickup boxes / item HUD. Recorder samples the player on a fixed 0.2 s grid (interpolated between frames: position lerp, attitude slerp of `body.quaternion`) from GO until results (~2.6 s past the finish). Splits = simT at each ring pass. Encoding: int16 per sample (x,y,z in dm, quaternion ×32767), base64; a ~4:50 run is ~27 KB. Replay: Catmull-Rom position + slerp; tested mean 0.04 m / max 0.13 m position error; brief attitude spikes up to ~9° during abrupt AI roll changes (5 Hz sampling). Local best ghost: `localStorage 'ulr3-ghost'` (works everywhere, incl. a local copy). Ghosts raced: your best + the 2 fastest others on the leaderboard (when db is on). HUD: POS among ghosts, ±split vs fastest ghost under the timer, ghost dots on the minimap. Results: you + ghosts; saves a new best.

**One-lap auto-restart (2026-11-07):** Time Trial is now a single lap (`nLaps()` = 1 when `ttActive`, else `LAPS` 3). When the lap ends, after the usual ~2.6 s glide, `ttNextRun()` saves the run (local best ghost / leaderboard if faster) and calls `beginRace()`. That puts the player back at the takeoff spot with the countdown and the new best as the ghost. The TT results screen is no longer shown (`showTTResults` is kept but not called). The time is GO → crossing the start ring again, so it includes the takeoff. Old 3-lap ghosts are rejected (`validRec` now allows only ≤ N+1 splits), so the first one-lap run sets a fresh best. Pause → back to title is how you leave. Headless test: three back-to-back runs at 101.7 / 97.0 / slower; best updated only when beaten, and each run restarted on the runway with the ghost loaded.

**Live** (`titleMode 'live'`, `liveActive`, 👥 LIVE button only shown when the room is available): each client sends its state as an `st` message on the lobby at 10 Hz while flying (2 s heartbeat otherwise; stops if `not_permitted`) and also as presence at 15 Hz (presence goes to the named room `ulr-live`). Both feed one `ingest()`, deduplicated by sender timestamp; pilots unheard for 8 s are dropped. Payload: `{v,m(mode: title|lobby|free|race|results),uid,rid(race id),s:[x,y,z,qx,qy,qz,qw,spd,thr],pr:[passed,finish],ra(host's race announce {id,at}),t(sender ms)}` (~130 bytes). Receivers keep a 48-sample buffer per peer, estimate offset as min(recv−t) relaxing 2 ms/sample, render 120 ms behind with lerp/slerp, extrapolate ≤0.5 s, hide after 3 s silence. Free flight: everyone in free flight sees each other. Live race: anyone in the lobby presses START LIVE RACE (or Enter/A); start = now+6 s announced in the state; lobby members (and anyone on a live results screen) who see it join, and the countdown is recomputed from wall-clock each frame, so GO lines up within clock skew. No AI, no pickups, no collisions between humans. Position = remote progress from their reported ring count + interpolated position. Results update live as others finish; RACE AGAIN announces a new race for everyone present. Lobby list shows each pilot's receive rate (Hz) and ~delay (recv − sender clock, includes clock skew). Two tabs of one person count as two pilots ("You (other tab)"). Confirmed working by Eric with two Chrome split-view tabs on 2026-11-07.

**Lobby diagnostics:** grey `diag v3` line under START LIVE RACE (st sent/heard, lobby and named-room peer counts, 4 s `ping` events sent/heard, errors). Remove once live play is proven with friends.

**Tests (jsdom harness):** time trial (record → save → replay fidelity → second run with ghost → normal race & free flight still OK), shared leaderboard (mock db/user: post, other user races your ghost, read-only user), live (3 clients on a mock room bus with 40–90 ms latency: lobby, announce/join, GO sync, B sees A within ~0.1 m of A's path ~120–150 ms ago, results both ways, rematch pulls in a results-screen player, free-flight visibility; run both with presence crossing and with presence isolated / messages only), plus headless Chrome screenshots. Also fixed: pickup boxes stayed invisible after free flight → race (`b.m.visible=true` when active).

**Still to measure for real:** latency and smoothness between two people on different machines; whether presence crosses between different accounts.

## Flight model (aerobatic since 2026-11-06; Arcade removed 2026-11-03)
Every plane (player, rivals, title demo, free-flight traffic) uses the same physics.
- **Attitude is a full 3D frame**: `r.f` (nose = flight path) and `r.u` (wing-up). `hd`/`pitch`/`bank` are derived each step (`syncAngles`). Any code that writes hd/pitch/bank directly (respawn, bonk, world bounds, ground bounce, ceiling) is picked up by `ensureAtt()`, which rebuilds the frame when those values changed. Mesh orientation is set from the frame (quaternion), plus a small visual angle-of-attack tilt under g.
- **Elevator = lift coefficient** c (fraction of max): `elevToC(e)`; neutral c = .25 = 1 g at trim 24 m/s (≈86 km/h). Back half keeps the old "pull = slower" curve (e=1 → 1.19); push goes through zero to C_MIN −0.7 (negative g, inverted flight needs ~¾ forward stick). Load factor n = c·(V/VSTALL)² + pitch damping (KD 1.2 × smoothed accel, fades out at high g) — keeps the phugoid from porpoising; hands-off settles at trim speed.
- **G limit** +6 / −3 (elevator authority caps c at G_MAX/q). **Stall barrier**: above ~1.35×VSTALL full back only pulls to c .97; below ~1.15–1.35×VSTALL the stick can drag it past c = 1 → stall. Stalled: lift capped at c .5, nose drops, spin/rudder logic as before. Recovers when c < .85 and V > 1.1·VSTALL, or automatically once V > 1.6·VSTALL. Extra stall trigger: V < .62·VSTALL while nose up (tail-slide/hammerhead).
- **Ailerons = roll rate** for the player: ROLL_MAX 2.0 rad/s (~115°/s), scaled by speed (35% at low speed). Dihedral: stick centred and |bank| < 70° → eases back toward level (.55·sin bank rad/s). Rudder yaws (.35) and rolls a little (.25).
- Induced drag uses the actual load factor (pulling costs energy). Constants: VSTALL 12, VTRIM 24, CD0 .0024, CI 230, PHI_MAX .85 (rival bank limit).
- **Engine power (raised 2026-11-06, "too anemic"):** TMAX 3.6 → **5.2**, GROUND_THRUST 4.2 → **5.6**. Effect: takeoff roll 11.4 s / 171 m → 7.1 s / 105 m; full-power climb ~3.9 → ~8.2 m/s; level top speed ~139 → ~168 km/h (√(TMAX/CD0)).
- Ground roll: ground accel = GT·thr − .9 − .004V² − g·sinθ. Takeoff rotation when V > max(1.1·VSTALL, hands-off speed for stick+trim). B = wheel brakes. Engine heats only in the air above 85% throttle.
- World ceiling 260 m for aerobatic room.

## Elevator trim (player)
D-pad ↑/↓ (keys T = nose down, G = nose up). Step .05, hold repeats after .35 s. D-pad direction follows the pitch setting (default up = dive, so d-pad up trims nose down). Range TRIM_DN −.35 … TRIM_UP +.6 ≈ hands-off 118 … 58 km/h. Reset to neutral on new race / respawn. HUD shows G and "TRIM ▲/▼ xx km/h" above the instrument strip (advisories moved up).

## Look views
Hold d-pad ←/→ (keys Z / C): snaps (~0.1 s) to a cockpit eye inside the helmet looking out past the strut, ~17° down, FOV 74 — for lining up on the runway. Release returns to chase cam. HUD shows "◀ LOOKING LEFT / RIGHT ▶".

## Chase camera
Normal flight: unchanged level-horizon chase. Past ~55–75° bank or ~35–57° pitch (or inverted) it blends (`camAero`) into a full attitude-following chase (behind the nose, camera up = wing-up) so loops and rolls don't flip.

## Rival pilots (aiControl)
Fly like a pilot: stick holds a target speed, throttle holds climb rate. On the aerobatic model they use an **autopilot inner loop**: the old speed-hold pitch law (γ̇ = 2(V−vcmd)/vcmd + 4·accel/vcmd − .55(n−1), pitch kept within −.9…+.6) is turned into the lift coefficient that produces it (`r.cAI`, capped at .92 so they stay out of the buffet); bank held with a proportional roll loop (AI_ROLLK 8) toward steer·PHI_MAX. Other behaviours:
- Corner speeds per ring from banked-turn radius that fits the next leg; braking distance (drag-only, ~1.4 m/s²) planned for this ring and the next.
- Follow the line from the previous ring (runway axis for the first pass); hairpins (≥90°) take the inside 3 m.
- Climb-out after takeoff at full power and ~17 m/s; climb speed 19 m/s when below the ring.
- Never bank harder than current speed safely allows. Missed ring → teardrop recovery.
- Difficulty (DIFFS): Easy/Normal/Hard set cruise skill, corner push (cf), throttle cap, sloppiness.
- **Power-bump fixes (2026-11-06)** — with TMAX 5.2 Hard rivals initially missed 4–8 rings/race by flying over them. Three changes:
  1. Throttle correction terms (vertical-speed and ±.3 speed nudges) scaled by 3.6/TMAX so loop gain is unchanged.
  2. While descending to a ring (eh < 0), rival throttle capped at 3.6/TMAX (the old full power) — otherwise they arrive too fast, pull up to brake and zoom over.
  3. Boosting, or faster than the stick can command (pcmd at −1 and V > vcmd+1): autopilot flies the flight path to the ring (γ̇ = 2.5·(asin(vsd/V) − pitch)) instead of speed-hold, which used to zoom them up.
- Sim medians (jsdom harness, all-AI races, pickups on, 6 races/difficulty). Pre-power-bump: Easy ~360 s, Normal ~341 s, Hard ~307 s. After: Easy ~328, Normal ~312, Hard ~298. Stalls 0; ring misses back to the pre-bump level (~9 per 3 Hard races). Note the player gains more from the extra power than rivals (rival cruise targets unchanged: 20+16·skill m/s), so races are somewhat easier — raise rival cruise if friends find it too easy.

**Missed rings (2026-11-07, player only, all race modes incl. Time Trial and Live):** crossing the target ring's plane outside the hole (within 110 m to the side, `MISS_LAT`), or sitting past its plane for >1 s without crossing (came in from the side), calls `missRing()`: "MISSED RING · 3 s PENALTY" banner + low buzz + rumble, ring flashes red, the ring counts as passed (`passRing(r,g,true)`, so laps/splits/finish still work) and the target moves to the next ring. Penalty `penT` = 3 s (`PEN_T`): speed cut to max(72 km/h, 75%) at the miss, then extra drag (V−PEN_V)·1.6 + .8 pulls it toward `PEN_V` 20 m/s; full control kept. Test: 137 → 99 km/h at once, holds ~80 km/h at full throttle, back to normal after 3 s. HUD shows "PENALTY · SLOWED x.x s". Replaces the old "MISSED RING · TURN BACK" warning. Rivals unchanged (still fly the teardrop back). AI-flown player sim: 1 genuine miss in 4 races, no false triggers.

## Course
14 rings; ring 0 raised to 14 m (runway clearance); ring 6 lowered (ALT 50) and ring 12 moved to ease the ring-11 hairpin to 96°. Grid at runway start (118/134 m behind ring 0); clear zone past the runway's departure end.

## Controls (controller)
Left stick fly (roll / pitch) / right stick throttle (swappable) · LT/RT rudder · LB/RB pickups · B brakes · A confirm/respawn · X free flight / runway reset · Start pause · Y mute · **D-pad ↑↓ trim, ←→ hold to look** (d-pad still navigates menus; it no longer flies the plane). Pitch default Up = dive. Keyboard: arrows/A-D fly, W/S throttle, Q/E rudder, T/G trim, Z/C look. Title mode row cycles Race → Time Trial → (Live, when available) → Free Flight.

**Non-standard layouts (2026-11-06):** a friend on Windows (likely Firefox) had rudder on View/Menu — the browser gave the raw DirectInput order instead of the W3C "standard" mapping. `stdPad()` now rebuilds a standard-shaped pad for Xbox-like ids (xbox/xinput/045e/microsoft) when `mapping !== 'standard'`: buttons A B X Y LB RB View Menu LS RS; triggers from a combined Z axis (axes[2], LT +, RT −) or two separate axes (2 and 5, auto-detected when both rest at −1); right stick axes 3/4; d-pad from hat axis 9, axes 5/6, or buttons 10–13. Title-screen pad status shows "Xbox fallback layout" plus live LT/RT values for checking. Combined-Z trigger sign is a best guess — if rudder is reversed for someone, flip it there. Chrome/Edge give the standard layout and are unaffected.

## Testing approach
Node + jsdom harness: loads the page with WebGL renderer, canvas 2D and rAF stubbed, injects `window.__T={ev:c=>eval(c)}` into the game closure, then steps `update(1/60)` (or `frame(t)` for HUD) directly. Fake pads via `navigator.getGamepads` stub; fake `window.claude.use('db'|'user'|'room')` mocks for the shared features. Scripts used: race medians per difficulty (finish times, ring misses, stalls, bonks), ring-miss diagnosis (height/lateral offset and boost state at each miss), ring-split traces, takeoff/climb comparison against the previous build, loop / roll / inverted / dihedral / trim / look / landing maneuvers, time-trial/ghost, leaderboard and live-room tests (see Multiplayer). Visual checks: Playwright + system Chrome (swiftshader).
