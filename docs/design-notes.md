Live game: https://claude.ai/artifact/JX51aHcu6bNdjfo7wtrYFE (single self-contained HTML, Three.js r159 inlined). Artifact UUID 8dde2439-b208-4790-a647-469bfc46d0ad. Declared capabilities (since 2026-11-07): `room`, `user {scopes:[profile]}`; runtime contract 0.2.96.
Source repo: https://github.com/etownson/ultralight-racing (private) — `index.html` is the published file; commit after each republish.

## Multiplayer (added 2026-11-07)
Plan agreed with Eric: (1) remote-plane layer, (2) time-trial ghosts + leaderboard, (3) live races over the artifact `room`. All three are in the code.

**Platform limits found (they decide the design):**
- **Sharing (as of 2026-11-07): private, friends invited by email** (Eric set it private on purpose so invited friends get room/admin access; link sharing stays off). Earlier it was publicly shared, and the platform refuses to add `db` to a public artifact, so the shared leaderboard is still dormant (the code is built and tested, `DB` stays null). Now that it's private it can be turned on: declare `db: {rules:[{path:"tt",read:"view",write:"owner"},{path:"tt/{self}",write:"interact"}]}` plus `user {scopes:[profile]}`. Even then, on a personal plan only the owner and **Editors invited by email** (while not link-shared) can write; outside Viewers only read.
- `room`: people arriving by **public link can't connect**; signed-in people invited by email can, even as Viewers. **Presence** is open to every admitted viewer (≤4 KiB, coalesced ~30/s; emits + presence share ~40/s). **Event topics** are admin-only (Editor and up) unless opened to Contributors (never Viewers).
- **Real-world test (Eric, two Chrome tabs, same account):** both tabs connected, but `onPeers`/presence listed only the tab itself, in the lobby and in a named room alike, while `emit`/`on` messages *did* cross between the tabs. So live state now travels as an `st` event message (owner/Editors can send), with presence kept as a fallback. Consequence for friends: an outside friend needs **"Can edit"** access, which only gives admin while the artifact is **not** also link-shared. Whether presence works between two *different* accounts (which would let plain Viewers play) is still untested.
- Friends need a (free) Claude account with the exact invited email; create the account first, then invite (re-invite if the invite went out before the account existed).

**Remote-plane layer** (`makeRemoteMesh`, `disposeRemote`, `fadeRemote`): plane mesh driven by samples, not physics. Ghost meshes are translucent (opacity ≤.45, no shadows, fade further when within ~17 m of the player); live players use normal opaque planes.

**Time Trial mode** (`titleMode 'tt'`, `ttActive`): `racers=[player]`, other planes hidden, grid centre, no pickup boxes / item HUD. Recorder samples the player on a fixed 0.2 s grid (interpolated between frames: position lerp, attitude slerp of `body.quaternion`) from GO until results (~2.6 s past the finish). Splits = simT at each ring pass. Encoding: int16 per sample (x,y,z in dm, quaternion ×32767), base64; a ~4:50 run is ~27 KB. Replay: Catmull-Rom position + slerp; tested mean 0.04 m / max 0.13 m position error; brief attitude spikes up to ~9° during abrupt AI roll changes (5 Hz sampling). Local best ghost: `localStorage 'ulr3-ghost'` (works everywhere, incl. a local copy). Ghosts raced: your best + the 2 fastest others on the leaderboard (when db is on). HUD: POS among ghosts, ±split vs fastest ghost under the timer, ghost dots on the minimap. Results: you + ghosts; saves a new best.

**One-lap auto-restart (2026-11-07):** Time Trial is now a single lap (`nLaps()` = 1 when `ttActive`, else `LAPS` 3). When the lap ends, after the usual ~2.6 s glide, `ttNextRun()` saves the run (local best ghost / leaderboard if faster) and calls `beginRace()`. That puts the player back at the takeoff spot with the countdown and the new best as the ghost. The TT results screen is no longer shown (`showTTResults` is kept but not called). The time is GO → crossing the start ring again, so it includes the takeoff. Old 3-lap ghosts are rejected (`validRec` now allows only ≤ N+1 splits), so the first one-lap run sets a fresh best. Pause → back to title is how you leave. Headless test: three back-to-back runs at 101.7 / 97.0 / slower; best updated only when beaten, and each run restarted on the runway with the ghost loaded.

**Live** (`titleMode 'live'`, `liveActive`, 👥 LIVE button only shown when the room is available): each client sends its state as an `st` message on the lobby at 10 Hz while flying (2 s heartbeat otherwise; stops if `not_permitted`) and also as presence at 15 Hz (presence goes to the named room `ulr-live`). Both feed one `ingest()`, deduplicated by sender timestamp; pilots unheard for 8 s are dropped. Payload: `{v,m(mode: title|lobby|free|race|results),uid,rid(race id),s:[x,y,z,qx,qy,qz,qw,spd,thr],pr:[passed,finish],ra(host's race announce {id,at}),t(sender ms)}` (~130 bytes). Receivers keep a 48-sample buffer per peer, estimate offset as min(recv−t) relaxing 2 ms/sample, render 120 ms behind with lerp/slerp, extrapolate ≤0.5 s, hide after 3 s silence. Free flight: everyone in free flight sees each other. Live race: anyone in the lobby presses START LIVE RACE (or Enter/A); start = now+6 s announced in the state; lobby members (and anyone on a live results screen) who see it join, and the countdown is recomputed from wall-clock each frame, so GO lines up within clock skew. No AI, no pickups, no collisions between humans. Position = remote progress from their reported ring count + interpolated position. Results update live as others finish; RACE AGAIN announces a new race for everyone present. Lobby list shows each pilot's receive rate (Hz) and ~delay (recv − sender clock, includes clock skew). Two tabs of one person count as two pilots ("You (other tab)"). Confirmed working by Eric with two Chrome split-view tabs on 2026-11-07.

**Lobby diagnostics:** grey `diag v3` line under START LIVE RACE (st sent/heard, lobby and named-room peer counts, 4 s `ping` events sent/heard, errors). Remove once live play is proven with friends.

**Tests (jsdom harness):** time trial (record → save → replay fidelity → second run with ghost → normal race & free flight still OK), shared leaderboard (mock db/user: post, other user races your ghost, read-only user), live (3 clients on a mock room bus with 40–90 ms latency: lobby, announce/join, GO sync, B sees A within ~0.1 m of A's path ~120–150 ms ago, results both ways, rematch pulls in a results-screen player, free-flight visibility; run both with presence crossing and with presence isolated / messages only), plus headless Chrome screenshots. Also fixed: pickup boxes stayed invisible after free flight → race (`b.m.visible=true` when active).

**Still to measure for real:** latency and smoothness between two people on different machines; whether presence crosses between different accounts.

## Combat mode (added 2026-11-07)
Eric's spec: dogfight mode for single player and co-op. Players take off from the runway; the enemies are already airborne. Shoot them all down. Single player: 10 enemies, too much damage = the plane blows up = game over. Co-op: more enemies, and a shot-down pilot is repaired on the runway for 30 s. Pickups give bullets (lots, fired in bursts, counted down) or 4 lock-on missiles.

**Title / controls:** ⚔ COMBAT button (`titleMode 'combat'`, remembered like the other modes); 👥 Live lobby has a second button, ⚔ START CO-OP COMBAT. Guns: Space / RB / touch USE, **hold** to keep firing bursts of 8 (0.06 s apart, 0.14 s gap, ~15 rounds/s held). Missile: X / LB / touch MSL (new button, combat only). Rings are hidden in combat (no ring passing or tube collisions); the race rivals are hidden; the course setting only moves the ? boxes.

**Player:** hull 100 %, starts with 200 rounds and 0 missiles. ? boxes (the race box positions, respawn 10 s, only you can take them; in co-op each pilot has their own boxes): 65 % +150 rounds (cap 999), 35 % +4 missiles (cap 12). Your rounds do 5 damage, with gun aim assist (below); missiles lock within 10° / 380 m, fly 66 m/s with a 2.6 rad/s turn limit (a hard break can beat one), lose lock when they overshoot, and kill on hit. Hitting the ground, a tree or a building wrecks the plane (the free-flight rules); a mid-air collision costs you 35 and the bandit 60. HUD: bandits left, kills, hull bar, ammo + missiles, timer, minimap (red diamonds = bandits, pink = boxes), red diamond markers on bandits in view (distance and health bar when close), arrow to the nearest bandit when none is on screen, gun sight with green hit marker, missile lock box, red damage vignette, smoke/fire trail when damaged, "BANDIT ON YOUR SIX · BREAK!" warning. Victory time per level saved in `ulr3-best` as `cb:<Level>`.

**Gun aim assist (2026-11-07, Eric: "a bit too frustrating"; missiles left as they were):** `CB_AIM = {cone:12, range:320, home:1.3, hitR:3.2}`. The bandit whose lead point is within 12° of the nose (closest to the nose wins, up to 320 m) gets each round aimed at its lead point, and the round then curves after it at up to 1.3 rad/s while it's still ahead; your rounds' hit radius went from 2.6 to 3.2 m. HUD: a lead marker (circle + dot, dashed line from the bandit) on the assisted bandit, yellow, turning green with "GUNS · ON TARGET" (and a green gun sight) when within 5° and 240 m. Test (one 8-round burst at a bandit 80–200 m ahead in a random turn, nose off the lead point by a given error): before, 0.7 / 0.2 / 0.1 / 0.1 hits at 0° / 3° / 6° / 10° off (even perfect aim missed a turning target); after, 7.3 / 6.7 / 5.5 / 3.6. With home 2.4 it was 6 hits even 10° off, too generous. The test pilot's hit rate in full sims went from ~25 % to ~65 %. Knobs: `home` (curve), `cone`, `hitR`.

**Enemies** (`foes[]`, separate from `racers`; dark grey with red helmets): the same aerobatic physics as everyone. `cbSteer(r, dir, gmax, thr)` turns "point the nose along dir" into a roll rate (`r.rollCmd`, a new path in `realisticFlight` for `team==='foe'`/`cbBot`) and a lift coefficient (`r.cAI`): roll the lift vector toward the needed turn + gravity compensation, then pull (pull scaled by cos(roll error)). `cbSafeDir` keeps them out of the ground (look-ahead + sink-rate check), the walls and the ceiling. Behaviour (`cbAI`): spawn airborne 55–100 m up, >230 m from the runway; patrol until a pilot has been airborne 4 s (or 25 s after GO); then up to `att` per pilot attack at once (lead pursuit, fire bursts inside a cone/range), each for one pass of `pass` seconds, then pull off 280 m and rest so others take turns; break when someone's on their tail (chance `brk`) or a missile is coming; break away from head-on/too close; don't fire at anyone on the ground or in the 6 s "fresh off the runway" window. Shot down: they spin down trailing fire and smoke and explode on the ground.

**Sim results** (jsdom, a test autopilot flying the player, `player.cbBot`): the bot is a poor dogfighter (it mostly gets caught from behind and breaks), so these are a floor, not what a person will see. Easy: survives 400 s, 4–5 kills, runs out of ammo (it doesn't fly to boxes). Normal: survives ~90–330 s, 0–3 kills. Hard: dies in 60–115 s. Enemy hit rate on an evading target ~15–25 %; 0 enemy ground crashes after the sink-rate check. Tuning knobs: `CB_DIFF` (all of the table), `CB_MY_DMG`, `CB_START_AMMO`, box odds in `cbPickup`. Balance still needs real play.

**Co-op** (over the same room/`st` messages as Live): the announce carries `k:'cb'`, the enemy count `n` = 10 + 4 per other pilot in the lobby (cap 24) and the starter's level `d` (everyone uses it). The starter's browser is the **host**: it simulates the enemies and adds `cbh` to its `st` state: `{n, e:[x,y,z,qx,qy,qz,qw,hp,state,firing]×n, ks:{pilotId:kills}, dm:[[pilotId,eventId,damage]], done, eg}` (~1.5 KB with 22 enemies). Every pilot adds `cbs:{me:SELF, hp, dn(0 flying / 1 wreck / 2 repairing), k, fg(firing), g(on ground), sf(safe), ms:[missile positions], h:[[hitId, enemyIdx, damage]]}`. `SELF` is a random id per tab. Guests draw the host's enemies 120 ms behind, interpolated (tested median error 0.13 m vs the host); their own rounds and missiles hit those drawn enemies and are reported in `h` (resent for 2.5 s, deduplicated by id); the host applies them and credits the kill. Enemy fire at a guest is resolved on the host against the guest's drawn position and sent back in `dm`. Tracers and missile smoke of other pilots and of the enemies are cosmetic on each screen. Shot down in co-op: wreck 2.5 s, then 30 s of repairs on the runway (no controls), then hull 100 %, ammo topped back up to 200, 6 s of protection after takeoff. Round ends for everyone when the host reports all down (CO-OP VICTORY, kills per pilot), or after 7 s without the host (ROUND OVER). FIGHT AGAIN from the results starts a new round (whoever presses it becomes the host). Pause in co-op shows the menu but the fight continues. **Limitation:** if the host's tab is hidden or the computer sleeps, the browser stops the game loop and the enemies freeze for everyone; the lobby text tells the starter to keep the game in view.

## Flight model (aerobatic since 2026-11-06; Arcade removed 2026-11-03)
Every plane (player, rivals, title demo, free-flight traffic) uses the same physics.
- **Attitude is a full 3D frame**: `r.f` (nose = flight path) and `r.u` (wing-up). `hd`/`pitch`/`bank` are derived each step (`syncAngles`). Any code that writes hd/pitch/bank directly (respawn, bonk, world bounds, ground bounce, ceiling) is picked up by `ensureAtt()`, which rebuilds the frame when those values changed. Mesh orientation is set from the frame (quaternion), plus a small visual angle-of-attack tilt under g.
- **Elevator = lift coefficient** c (fraction of max): `elevToC(e)`; neutral c = .25 = 1 g at trim 24 m/s (≈86 km/h). Back half keeps the old "pull = slower" curve (e=1 → 1.19); push goes through zero to C_MIN −0.7 (negative g, inverted flight needs ~¾ forward stick). Load factor n = c·(V/VSTALL)² + pitch damping (KD 1.2 × smoothed accel, fades out at high g) — keeps the phugoid from porpoising; hands-off settles at trim speed.
- **G limit** +6 / −3 (elevator authority caps c at G_MAX/q). **Stall barrier**: above ~1.35×VSTALL full back only pulls to c .97; below ~1.15–1.35×VSTALL the stick can drag it past c = 1 → stall. Stalled: lift capped at c .5, nose drops, spin/rudder logic as before. Recovers when c < .85 and V > 1.1·VSTALL, or automatically once V > 1.6·VSTALL. Extra stall trigger: V < .62·VSTALL while nose up (tail-slide/hammerhead).
- **Ailerons = roll rate** for the player: ROLL_MAX 2.0 rad/s (~115°/s), scaled by speed (35% at low speed). Dihedral: stick centred and |bank| < 70° → eases back toward level (.55·sin bank rad/s). Rudder yaws (.35) and rolls a little (.25).
- Induced drag uses the actual load factor (pulling costs energy). Constants: VSTALL 12, VTRIM 24, CD0 .0024, CI 230, PHI_MAX .85 (rival bank limit).
- **Engine power (raised 2026-11-06, "too anemic"):** TMAX 3.6 → **5.2**, GROUND_THRUST 4.2 → **5.6**. Effect: takeoff roll 11.4 s / 171 m → 7.1 s / 105 m; full-power climb ~3.9 → ~8.2 m/s; level top speed ~139 → ~168 km/h (√(TMAX/CD0)).
- Ground roll: ground accel = GT·thr − .9 − .004V² − g·sinθ. Takeoff rotation when V > max(1.1·VSTALL, hands-off speed for stick+trim). B = wheel brakes. Engine heats only in the air above 85% throttle.
- World ceiling 260 m for aerobatic room.

## Elevator trim (player)
D-pad ↑/↓ (keys T = nose down, G = nose up). Step .05, hold repeats after .35 s. D-pad direction follows the pitch setting (default up = dive, so d-pad up trims nose down). Range TRIM_DN −.35 … TRIM_UP +.6 ≈ hands-off 118 … 58 km/h. Reset to neutral on new race / respawn. HUD shows G and "TRIM ▲/▼ xx km/h" above the instrument strip (advisories moved up).

## Look views
Hold d-pad ←/→ (keys Z / C): snaps (~0.1 s) to a cockpit eye inside the helmet looking out past the strut, ~17° down, FOV 74 — for lining up on the runway. Release returns to chase cam. HUD shows "◀ LOOKING LEFT / RIGHT ▶".

## Chase camera
Normal flight: unchanged level-horizon chase. Past ~55–75° bank or ~35–57° pitch (or inverted) it blends (`camAero`) into a full attitude-following chase (behind the nose, camera up = wing-up) so loops and rolls don't flip.

## Rival pilots (aiControl)
Fly like a pilot: stick holds a target speed, throttle holds climb rate. On the aerobatic model they use an **autopilot inner loop**: the old speed-hold pitch law (γ̇ = 2(V−vcmd)/vcmd + 4·accel/vcmd − .55(n−1), pitch kept within −.9…+.6) is turned into the lift coefficient that produces it (`r.cAI`, capped at .92 so they stay out of the buffet); bank held with a proportional roll loop (AI_ROLLK 8) toward steer·PHI_MAX. Other behaviours:
- Corner speeds per ring from banked-turn radius that fits the next leg; braking distance (drag-only, ~1.4 m/s²) planned for this ring and the next.
- Follow the line from the previous ring (runway axis for the first pass); hairpins (≥90°) take the inside 3 m.
- Climb-out after takeoff at full power and ~17 m/s; climb speed 19 m/s when below the ring.
- Never bank harder than current speed safely allows. Near miss → 5 s penalty (all difficulties); wide miss → teardrop recovery.
- Difficulty (DIFFS): Easy/Normal/Hard set cruise skill, corner push (cf), throttle cap, sloppiness.
- **Power-bump fixes (2026-11-06)** — with TMAX 5.2 Hard rivals initially missed 4–8 rings/race by flying over them. Three changes:
  1. Throttle correction terms (vertical-speed and ±.3 speed nudges) scaled by 3.6/TMAX so loop gain is unchanged.
  2. While descending to a ring (eh < 0), rival throttle capped at 3.6/TMAX (the old full power) — otherwise they arrive too fast, pull up to brake and zoom over.
  3. Boosting, or faster than the stick can command (pcmd at −1 and V > vcmd+1): autopilot flies the flight path to the ring (γ̇ = 2.5·(asin(vsd/V) − pitch)) instead of speed-hold, which used to zoom them up.
- Sim medians (jsdom harness, all-AI races, pickups on, 6 races/difficulty). Pre-power-bump: Easy ~360 s, Normal ~341 s, Hard ~307 s. After: Easy ~328, Normal ~312, Hard ~298. Stalls 0; ring misses back to the pre-bump level (~9 per 3 Hard races). Note the player gains more from the extra power than rivals (rival cruise targets unchanged: 20+16·skill m/s), so races are somewhat easier — raise rival cruise if friends find it too easy.
- **Harder Hard (2026-11-07)** — Eric was beating Hard by ~1 min/race; Hard was already at the top of every old knob. Diagnosis with a limiter trace (which speed cap binds each frame): rivals spent ~48% of the race held by the *turn-in* limit (radius to a chase point only 15–60 m ahead), plus climb-speed blending whenever a ring was above, a climb-out mode that fired whenever below 20 m AGL, and a timid throttle loop — average ~85 km/h vs a 130 km/h cruise. Hard-only flags in `DIFFS[2]` (Easy/Normal untouched, verified by sim):
  - `ti` "sharp pilot": turn-in judged against the ring itself (`max(d,dRing)`, angle to ring) with margin `tim` .6; hairpin cap 24·kV instead of 21; full throttle when >2 m/s under target (not descending); climb-out only off the runway (`passed===0`); slows to climb speed `vcl` 22 m/s only when the climb gradient to the ring exceeds `cg` .08; vertical-speed target from time-to-ring (sink to −14, climb to `vsu` 10 m/s); **near misses use the player's rule** (`aiMissRing`: 5 s slowdown, ring counts) instead of the teardrop — extended to Easy/Normal later the same day (`aiPenRules` no longer checks `ti`).
  - `phi` 1.3 rad (~74°) bank limit, with corner/turn speeds scaled by kV = √(tan φ / tan PHI_MAX); `r.phi` also drives the roll loop in physics.
  - `pm` 250: inside 250 m of the ring the autopilot flies the flight path to ring height (the boost-mode law) instead of speed-hold — fixed most vertical misses at speed.
  - `co` 21 m/s climb-out speed; `vc` cruise multiplier exists but stays 1 (1.1 → ~5 s faster but more misses).
  - Result (20 all-AI Hard races): median 222 s (was ~295), median winner ~219, fastest ~207; ~0.4 misses/racer/race; 0 stalls. If still too easy: `vc` 1.1–1.2, then `phi` 1.35. Harness scripts were rebuilt this session (sim.js, trace.js, lim.js limiter trace, miss.js miss classifier) but live only in the session workspace.

**Missed rings (2026-11-07, player only, all race modes incl. Time Trial and Live):** crossing the target ring's plane outside the hole (within 110 m to the side, `MISS_LAT`), or sitting past its plane for >1 s without crossing (came in from the side), calls `missRing()`: "MISSED RING · 5 s PENALTY" banner + low buzz + rumble, ring flashes red, the ring counts as passed (`passRing(r,g,true)`, so laps/splits/finish still work) and the target moves to the next ring. Penalty `penT` = 5 s (`PEN_T`; was 3 s, raised same day after Eric played it): speed cut to max(72 km/h, 75%) at the miss, then extra drag (V−PEN_V)·1.6 + .8 pulls it toward `PEN_V` 20 m/s; full control kept. Test: 137 → 99 km/h at once, holds ~80 km/h at full throttle, back to normal when the penalty ends. HUD shows "PENALTY · SLOWED x.x s". Replaces the old "MISSED RING · TURN BACK" warning. Rivals on every difficulty take the same 5 s penalty for a near miss (since 2026-11-07; before that only Hard did, and Easy/Normal flew the teardrop). Wide misses (more than `MISS_LAT` to the side) still fly the teardrop. AI-flown player sim: 1 genuine miss in 4 races, no false triggers.

## Courses (four since 2026-11-07)
Selector on the title menu: **COURSE** row (first row under the modes; ◀ ▶, or d-pad/arrow keys), with a one-line description under it. Remembered in `localStorage 'ulr3-course'`. Order: Lazy Sunday · Hump Day (default) · Manic Monday · Freaky Friday. Data lives in `COURSES` (`id`, `n`, `tag`, `raw` plan coords, `alt` ring heights above ground).
- All courses share the map, runway and ring 0 (14 m over the runway); the runway frame is fixed from Hump Day's geometry. 14 rings each, so laps/splits/ghost code is unchanged.
- **Hump Day** (the original): avg turn 46°, max 96°; ring-to-ring height change avg 14 m, max 26 m. Ring 0 raised to 14 m (runway clearance); ring 6 lowered (ALT 50) and ring 12 moved to ease the ring-11 hairpin to 96°.
- **Lazy Sunday**: smooth flatter loop, avg turn 29°, max 46°; height change avg 8 m, max 12 m (gradients ≤ 9%). Lap ~1755 m. Ring 13 moved to (-330,115) world so Hard rivals stop overshooting ring 0.
- **Manic Monday**: avg turn 59°, max 108° (hairpins at rings 4 and 7); height change avg 18 m, max 30 m (gradients to ~21%). Lap ~2020 m. Ring 7 lowered and ring 9/10 eased after the AI-player sim missed them a lot.
- **Freaky Friday** (added the same day): avg turn 76°, max 118° (hairpins at rings 4, 5, 10, 11); every leg a big climb or dive, height change avg 30 m, max 42 m (gradients to ~30%), ring heights 23–76 m. Lap ~2095 m. Design lessons from its tuning: (1) keep hairpins ≤ ~120° — a ring's plane faces prev→next, so in a sharper zig-zag you cross it nearly sideways and the AI (and players) miss; (2) keep rings ~20+ m inside the map edges (|x| ≲ 315, |z| ≲ 195) — rings at x ±330–340 were circled, not flown through. First draft: 9 misses/race on Easy and 8–12-min races; final: ~2 misses/race on Easy, ~1.3 on Hard.
- Switching (`applyCourse(i)`): re-lays the rings (`layoutRings`), AI corner speeds, ring meshes + buoys, pickup boxes, and re-subscribes the leaderboard. Trees and houses avoid the rings of *every* course (`allRingXZ`).
- **Per-course records**: Hump Day keeps the old keys so existing records survive (`ulr3-best` key = difficulty name, `ulr3-ghost`, db collection `tt`). Others: best key `lazy:Normal` etc., ghost `ulr3-ghost-lazy` / `-manic` / `-freaky` (runs carry `c`), db collections `tt-lazy` / `tt-manic` / `tt-freaky` (each needs its own db rules when the leaderboard is switched on).
- **Live**: the host's race announce carries the course (`ra.c`); everyone who joins switches to it. Presence carries `c`; the lobby list shows each pilot's course and the start button says which course the race will use.
- Sim medians (all-AI, 3–8 races per cell): Lazy Easy ~288 / Normal ~280 / Hard ~180 s; Hump ~316 / ~310 / ~225 s; Manic ~350 / ~370 / ~243 s; Freaky ~413 / ~429 / ~274 s (slow Easy/Normal rivals climb slowly). 0 stalls, 0 DNFs; Hard misses ~0.4–0.75 per racer per race (Manic highest).
Grid at runway start (118/134 m behind ring 0); clear zone past the runway's departure end.

## Controls (controller)
Left stick fly (roll / pitch) / right stick throttle (swappable) · LT/RT rudder · LB/RB pickups · B brakes · A confirm/respawn · X free flight / runway reset · Start pause · Y mute · **D-pad ↑↓ trim, ←→ hold to look** (d-pad still navigates menus; it no longer flies the plane). **Non-standard layouts (2026-11-06):** a friend on Windows (likely Firefox) had rudder on View/Menu — the browser gave the raw DirectInput order instead of the W3C "standard" mapping. `stdPad()` now rebuilds a standard-shaped pad for Xbox-like ids (xbox/xinput/045e/microsoft) when `mapping !== 'standard'`: buttons A B X Y LB RB View Menu LS RS; triggers from a combined Z axis (axes[2], LT +, RT −) or two separate axes (2 and 5, auto-detected when both rest at −1); right stick axes 3/4; d-pad from hat axis 9, axes 5/6, or buttons 10–13. Title-screen pad status shows "Xbox fallback layout" plus live LT/RT values for checking. Combined-Z trigger sign is a best guess — if rudder is reversed for someone, flip it there. Chrome/Edge give the standard layout and are unaffected.

## Testing approach
Node + jsdom harness: loads the page with WebGL renderer, canvas 2D and rAF stubbed, injects `window.__T={ev:c=>eval(c)}` into the game closure, then steps `update(1/60)` (or `frame(t)` for HUD) directly. Fake pads via `navigator.getGamepads` stub; fake `window.claude.use('db'|'user'|'room')` mocks for the shared features. Scripts used: race medians per difficulty (finish times, ring misses, stalls, bonks), ring-miss diagnosis (height/lateral offset and boost state at each miss), ring-split traces, takeoff/climb comparison against the previous build, loop / roll / inverted / dihedral / trim / look / landing maneuvers, time-trial/ghost, leaderboard and live-room tests (see Multiplayer). Visual checks: Playwright + system Chrome (swiftshader).

**Miss penalty on Easy/Normal (2026-11-07):** sim (4 all-AI races per cell, rivals' median finish): Hump Day Easy ~332 → ~303 s, Normal ~309 → ~302 s; Freaky Friday Easy ~410 → ~390 s, Normal ~480 → ~405 s. Easy/Normal rivals now log ~2–3 penalties per race on Hump and ~4–13 on Freaky (they miss often, but no longer lose 20–60 s circling back), with a few wide-miss teardrops left on Freaky. Net effect: Easy/Normal rivals are a bit faster and finish closer together, most of all on the twisty courses. 0 stalls.
